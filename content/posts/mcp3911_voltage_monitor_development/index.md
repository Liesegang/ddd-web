作りたかったのは、IoTデバイスの消費電力を測る道具でした。
無線送信時のピーク電流、センサーを読む間の負荷、スリープへ入ったあとの電流を分けて記録しなければ、電池寿命の見積もりは平均値の推測で終わってしまいます。

テスターの数字を見ている最中に、電源電圧側で何が起きていたのか。
プローブを持ち替えた時点で、その瞬間はもう戻ってきません。

オシロスコープを使えば解決します。
ただ、机の上で毎回きちんと構えるほどではない測定や、持ち出してしばらく記録したい測定もあります。
そこで、二つの電圧を同時に測り、その場では数字を、必要になったらブラウザで波形を見られる小さな測定器を作りました。

{{< img800x src="mcp3911/device.jpg" alt="完成したMCP3911 2チャンネル電圧／電流測定器" >}}

## 一つの基板に二つの役割を持たせる

最初に欲しかったのは、PCなしで使える電圧計でした。
ところが、現在値だけでは変動の原因を追えません。
ロガーを別に作ればよいとは思うものの、測定入力と校正を二組用意するのは惜しい。

同じ測定回路を、表示器にもロガーにも使うことにしました。

USBを外している間は、STM32C011が取得した二つの値を128 × 64のOLEDへ表示します。
USBでブラウザへ接続すると、測定値はFT234XD経由でPCまたはAndroid端末へ流れ、時間波形、FFT、統計値、演算結果として表示されます。

| ブロック | 採用した部品・方式 | 役割 |
| --- | --- | --- |
| アナログ入力 | MCP3911 | 2チャンネルの差動電圧を同時変換 |
| 制御 | STM32C011F6 | ADC制御、表示、データ送信 |
| ローカル表示 | 128 × 64 OLED | PCなしで現在値を確認 |
| PC接続 | FT234XD / USB Type-C | 1.5 Mbaudのシリアル通信 |
| 携帯電源 | 1セルLiPo / MCP73831 | USBを外した状態での動作と充電 |
| 解析 | React / Vite | ブラウザ上で記録、演算、FFT、CSV処理 |

## 同期していることが測定値になる

電圧と電流から瞬時電力を求めるなら、二つの値は同じ時刻のものでなければなりません。
入力と出力の位相差を見る場合も、チャンネル切替の時間差はそのまま測定誤差になります。

MCP3911は二つのADCを内蔵し、両チャンネルを同時に変換できます。
今回は16 MHzのMCLK、PGA 1倍、OSR 4096とし、変換速度を976.5625 samples/sに設定しました。
ADCから受け取る値は、各チャンネル24-bitの符号付き整数です。

```text
AMCLK = 16 MHz
DMCLK = AMCLK / 4 = 4 MHz
DRCLK = DMCLK / 4096 = 976.5625 Hz
```

高いサンプルレートだけを狙った設定ではありません。
数百Hzまでの低周波信号を二本同時に追いながら、電池駆動できる基板とブラウザの双方で扱いやすい地点を選びました。

## 50 mm角に測定系と電源系を収める

{{< img800x src="mcp3911/board.png" alt="EAGLEで設計した50 mm角2層基板のレイアウト" >}}

基板は50 mm × 50 mmの2層です。
右側に四つの測定端子と入力フィルター、中央にMCP3911とSTM32、左側にUSB、下側にLiPoの充電回路を配置しました。

各入力には1 kΩの直列抵抗、0.1 µFのコンデンサー、330 kΩのGND抵抗があります。
MCP3911の内蔵1.2 V基準とPGA 1倍で精度が規定される差動入力範囲は、約−0.6〜0.6 Vです。

ここは使い勝手より先に守るべき条件があります。
四つの入力端子は、基板GNDに対してそれぞれ−1〜1 Vへ収める必要があり、入力は絶縁されていません。
商用電源や高電圧へ直接つなぐ測定器ではなく、低電圧回路の微小な差動電圧を追うための構成です。

{{< img800x src="mcp3911/schematics.png" alt="MCP3911、STM32、USB、充電回路を含む回路図" >}}

電圧だけを測る場合、TH1–TH2間のR1とTH3–TH4間のR2は実装しません。
電流を測る場合は、測定電流と許容損失に合うシャント抵抗を必要なチャンネルへ実装します。
同じフットプリントを、用途によって空けるか埋めるかで使い分けます。

## 250 nsのパルスを待たない

ADCのデータ準備完了を知らせるDRパルスは、今回のクロック設定では約250 nsです。
GPIOをループで監視すれば読めそうに見えますが、短いパルスは処理のタイミング次第で通り過ぎます。

ファームウェアではDRピンをポーリングせず、MCP3911の`STATUSCOM`レジスターにある`DRSTATUS`を確認します。
この状態は両チャンネルのレジスターを読むまで保持されるため、ソフトウェアが一瞬遅れても変換完了を見失いません。
準備ができたらChannel 0とChannel 1の合計6 byteをSPIで連続して読み、各24-bit値を`int32_t`へ符号拡張します。

ADCコードから差動電圧への換算は次の式です。

```text
Vdiff = code × 1.2 / (2^23 × 1.5 × PGA)
```

係数1.5は実測から合わせ込んだ補正値ではなく、MCP3911の伝達関数に含まれる値です。
見た目のよい波形を作るための移動平均や指数平滑化も、ファームウェアでは行っていません。
ノイズを含め、ADCが返したものをホスト側で判断できるようにしました。

## シリアル通信は壊れる前提で区切る

二つの値をテキストで送る実装は簡単です。
しかし約977組のサンプルを毎秒送り、取りこぼしや途中接続も検出するなら、文字列の区切りだけでは心細くなります。

そこでUARTのデータは20 byte固定長のバイナリフレームにしました。

| オフセット | 長さ | 内容 |
| ---: | ---: | --- |
| 0 | 2 | 同期語 `A5 5A` |
| 2 | 1 | プロトコルバージョン |
| 3 | 1 | OLED表示状態 |
| 4 | 2 | シーケンス番号 |
| 6 | 4 | デバイス時刻（ms） |
| 10 | 4 | Channel 0 |
| 14 | 4 | Channel 1 |
| 18 | 2 | CRC-16/CCITT-FALSE |

同期語でフレームの先頭を探し、シーケンス番号で欠落を数え、CRCで破損を検出します。
ブラウザから500 msごとにキープアライブを送り、2秒間途絶えたらSTM32は送信を止めてOLED表示へ戻ります。
ケーブルを抜いたあと、基板が「Web接続中」のまま取り残されないための処理です。

## ブラウザを解析器にする

{{< img800x src="mcp3911/dashboard.png" alt="時間波形、統計値、演算ラインを表示したWebダッシュボード" >}}

デスクトップ版ChromeとEdgeではWeb Serialを使います。
Android版ChromeではFT234XD用のWebUSB polyfillへ切り替える実装にしました。
現時点でAndroid実機は未検証で、Web SerialとWebUSBを使えないiPhoneおよびiPadには対応していません。

ADCは常に976.5625 samples/sで動きます。
画面のSample rateを下げてもADC設定は変えず、UARTへ送るフレームを整数分周で間引きます。
さらに、シリアル受信とグラフ描画を分離し、表示更新だけを最大30 Hzに制限しました。

この区別がないと、描画を軽くするために測定データまで減らしてしまいます。
欲しいのは滑らかなアニメーションではなく、あとから調べられる記録です。

FFTは最大4096点を使い、DC成分を除去してHann窓をかけた片側RMSスペクトラムを表示します。
時間波形の選択範囲だけをCSVへ保存し、あとで同じダッシュボードへ読み戻すこともできます。

## 作例：IoTデバイスの消費電力量を出す

低電圧で動くIoTデバイスを観察する場合、Channel 0で負荷の端子間電圧を、Channel 1でシャント抵抗の電圧降下を同時に測ります。
0.1 Ωのシャント抵抗を使ったとき、電流はオームの法則から次の式になります。

```text
channel1 / 0.1
```

同じ時刻の負荷電圧と掛ければ、瞬時電力を求められます。

```text
channel0 * channel1 / 0.1
```

演算ラインには現在値、平均値、最小値、最大値、Peak-to-peakに加えて時間積分が表示されます。
平均電流が小さく見えても、起動、無線送信、センサー読み出し、スリープへの遷移はそれぞれ異なる波形になります。
その差が時間波形と積分値に残るため、動作周期を変えたときの電池寿命を実測値から比較できます。

シャントの向きによって電流や電力が負になる場合があります。
これは演算の失敗ではなく、Channel 1が`V(TH4) - V(TH3)`という極性で測っているためです。
端子を入れ替えるか、式の符号を反転すれば向きをそろえられます。

## 作ってわかったこと

OLEDを載せるだけなら、ここまでの通信機能は要りませんでした。
ブラウザで波形を見るだけなら、電池も表示器も省けました。
それでも両方を一枚に載せたことで、現場で数字を見て気になった変化を、そのまま同じ測定系で記録へ移せます。

一方で、この基板はオシロスコープや絶縁計測器の代わりではありません。
約488 Hzのナイキスト周波数を十分に下回る信号が対象で、入力範囲と対GND電圧の制約もあります。
用途を低電圧・低周波の2チャンネル計測へ絞ったからこそ、50 mm角とWebブラウザという軽い構成に収まりました。
